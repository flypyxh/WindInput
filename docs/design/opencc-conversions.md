# rime-frost 的 OpenCC 转换：与注释、追加通路的对照与落点

> 2026-10-10 设计稿。来源：rime-frost 拼音词库之外的 OpenCC 转换（emoji / others / 中英 / 拆分 / 火星文）
> 我们都没用（`schema-dict-discovery.md` §1 把它们留到这里）。关联看板 C2-54（GH#159 表情 / 符号覆盖）、
> E-5（t54「简入繁出时拆分显示繁体拆分」仍未核对）。续篇性质的已有设计：`emoji-suggestion.md`（已实现）、
> `text-mapping-tables.md`（未实施的多表框架）、`candidate-comment-layering.md`（注释分层）。

## 1 结论先行

**不引入 OpenCC 引擎**（不解释它的 JSON 配置、不做 mmseg 分词与转换链）。rime-frost 实际用到的五类转换，
全部落到我们已有的四条通路上；要补的是**数据格式的接受面**与少量挂接。

分界线：**接受 OpenCC 的数据格式，不接受它的转换配置。**

- OpenCC 的转换配置是为**整句**转换设计的；rime 把它当过滤器，对**每一条候选**做全文分词转换。
- 我们三条查表通路都是对候选文本**整词点查**，且只查可见页（注释，5～9 条）或前 `max_hosts` 条（追加），
  每条一次 mmap 二分 × 挂载库数，微秒级。rime-frost 的五张表没有一张需要分词或转换链。

## 2 格式：OpenCC 文本词典不是规范，是约定

- OpenCC 项目自己的约定（无独立规范文档）：一行一条 `键<Tab>值1 值2 …`，UTF-8，值以空格分隔，首个为
  默认转换。没有注释语法——rime-frost 的 `----------假装这是注释` 行是借「键不可重复」塞进去的。
- 「**值的首项重复键本身**」（`好	好 👌`）**不是 OpenCC 的要求**，是 rime simplifier 的用法约定：simplifier
  用转换结果替换原候选，要保住原词就得把它写成首项。OpenCC 自己的简繁表不遵守它（`干	干 幹 乾` 的首项
  恰好等于键只是巧合）。
- ⇒ 我们的解析规则：**值首项等于键则丢弃**（与 `emojidict::parse_upstream` 一致）；跳过以 `#` 或 `---`
  开头的行。带不带首项重复的表都能读，用户从 rime 生态拿来的表可以直接放。

## 4 与 `${dict}` 注释的重叠（本稿核心）

`${dict}` = 整词精确匹配 → 注释文字（`.wcmt` mmap 二分，`[[ui.comment_dicts]]` 挂载、数组序即优先级，
只查可见页）。与 OpenCC「词→值」结构相同。重叠处与处理：

1. **中英翻译走注释，不追加候选**（维护者定）。不占候选位、不影响排序与自动上屏；以后真要追加，
   同一张表再加一个呈现选项，不另起数据。
2. **格式**：注释词库解析接受 OpenCC 格式（§2 规则）。否则直接挂会显示「好 good well」多一个「好」。
3. **出厂模板是否预留 `{ ${dict}}`**：后续再定（维护者）。不预留时，用户勾选注释词库后还要自己改模板才
   生效——文档与设置端须写明这一步。
4. **emoji 的 `${emoji}` 注释档**与 `${dict}` 是两套通路。rime-frost 的 emoji 只走追加，不新增第三套
   注释通路。

拆分（chaifen）**不走 `${chaizi}`**（2026-10-10 核实后改）：拼音方案的 `${chaizi}` 刻意回落**全局主码表**
（通常五笔）的字根反查（`EngineManager::chaizi_spec`），挂墨奇拆分就得替换掉它或改这条回落规则。改为
把拆分也当注释库，用 `${dict:id}` 与中英释义并排（`${dict}` 只回第一个命中的库，单字「好」两者只能
显示其一）。拆分库只收单字键，正好对应 rime 的 `tips: char`。

## 5 灵活与性能

| 维度 | 取舍 |
|---|---|
| 用户自带表 | 三条通路都接受 OpenCC 文本格式 ⇒ rime 生态的表可直接放 |
| 开关代价 | 一表一文件一缓存，按内容指纹（`cache_fp`）建一次，之后 mmap；开关 = 挂 / 卸 reader，不重建 |
| 按键路径 | 不变：整词点查，可见页 / 前几条，O(log n) × 库数 |
| 一次性加载 | 最大的中英表 1.9 MB，首次建缓存；数字实施时实测 |
| 配置面 | 表的固有属性写在表里，用户配置只留开关（`text-mapping-tables.md` §4.2 原则） |

## 7 许可

rime-frost 为 GPL-3.0；墨奇拆分源自 `gaboolic/moqima-tables`（MIT）。即便如此，维护者定**暂不随包**注释
词库（中英 / 英中 / 拆分），待版权梳理后再议；届时登记方式倾向「`schemas/comments/` 目录自动识别、默认关、
空壳按 id 认领开关」——写进出厂 `config.toml` 的话，用户在设置里改过一次列表就整份固化（数组整体覆盖），
之后新增的随包词库对他不可见。
