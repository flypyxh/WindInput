# 覆盖的呈现规范（跟随 / 自定义）

状态：设计已定（2026-09-24），未实施。
来源：看板 C2-26 / C2-41（方案覆盖 config）、C2-20（设置项隐藏）、C0-7（按应用切方案）讨论中，
发现「一个值可以跟随上一层、也可以自定义」在设置端已有五种呈现写法，每新增一项就各写各的。
本文定下呈现层的规则，落到 `docs/architecture/config-design-rules.md` 新增的 **R8**；存储层仍归 R3 管。

## 1. 问题

「跟随 / 自定义」出现在两类地方：

- **作用域覆盖**：同一个设置在不同作用域取不同值（方案覆盖全局，将来还有应用覆盖）；
- **来源覆盖**：同一个设置有预设来源（主题）与手工值两个来源（外观页覆盖主题）。

R3 只规定了存储（`Option<T>` 或 `""` / `0` 哨兵，禁 `*_follow_theme`），没规定界面。现状（2026-09-24 调研）：

| 写法 | 用在哪 | 问题 |
|---|---|---|
| ① 勾选行：行首勾选 = 自定义，不勾时只读显示跟随值 + 来源色 | 方案 · 码表配置（`widgets.rs` `setting_row_override` / `schema_codetable.rs`） | 无，作为标杆 |
| ② 下拉/分段里带「跟随全局」档 | 方案 · 辅助码启用（分段）、标点、候选排列、overlay 排列 | 不显示跟随的是什么值；辅助码的设计文档（`aux-code-settings-ui.md` P3）本要求用 ① |
| ③ 勾选 + 内容，按「键在不在」区分 | 方案 · 候选注释、自定义标点表（子对话框） | 与 ① 同义，只是放在子对话框里，可保留 |
| ④ 哨兵值直接进控件 | 字号 `0`、字体 `""`、字重 `0`、翻页栏/页码 `""`、主字颜色 `""`、角标颜色 `auto` | 同样表示跟随主题，界面上分别叫「默认」「默认（主题配置）」「跟随主题」，字号只在 hint 里说明 |
| ⑤ 色值 6 位 / 8 位区分「跟随全局透明度」 | 角标颜色 | R3 列出的两种合法写法里没有这一种 |

另外：全局页只有「**可**被方案覆盖」的静态提示，没有「**已**被某方案覆盖」的实际状态，
用户改了全局值不生效时无从排查。

## 2. 规则（将写入 config-design-rules.md R8）

**R8.1 标准形态是勾选行（①）。** 行首勾选框表示「自定义」：
- 勾上：显示可编辑控件，写入值；
- 不勾：控件只读，显示**实际生效值 + 来源**，例如「跟随全局（开）」「跟随主题（18）」，写回「未设置」（`null` / 删键 / R3 哨兵）。

作用域覆盖与来源覆盖都用它。放进子对话框时（③）语义相同，允许。

**R8.2 枚举型字段可以用下拉（②）**，条件是字段本身是枚举、且选项 ≤ 6。「跟随」档放第一项，
**必须带值**，写成「跟随全局（横排）」；跟随值变了，这一档的文案要跟着变。

**R8.3 文案只用三个词**：「跟随全局」「跟随主题」「跟随方案」。禁用「默认」「自动」表示跟随。
「默认」只能指出厂值，二者不是一回事：跟随主题时，主题的值可能不等于出厂值。

**R8.4 存储仍按 R3**，禁止新的哨兵形态（如 ⑤ 的位长编码）。一项里包含两个独立的跟随维度时
（角标：颜色跟随主字、透明度跟随全局），拆成两个键，各自三态。

**R8.5 每个可覆盖区块都要有「全部恢复跟随」**。它只清**本区块界面上可见**的字段；
要清掉不可见字段时，必须在确认框里列出受影响的字段数。
（现状：码表「全部恢复跟随」会把 `SPEC_BEHAVIOR_FIELDS` 全集都清掉，包括界面上看不到的字段。）

**R8.6 被覆盖的一方要能反查。**
- 全局页：可覆盖项的角标从「可被方案覆盖」升级为「已被 N 个方案覆盖」（N = 0 时维持现状），
  悬停列出方案名，点击打开对应方案的设置；
- 外观页：`跟随主题（值）` 本身就说明了来源，不需要另加角标。

**R8.7 列表式（只列已覆盖项 + 手动添加）只用于「字段多、覆盖稀疏」的作用域**，
判据是可覆盖字段 > 30 个、而单个作用域通常只覆盖其中少数几项。
C2-26 的通用 config 覆盖（上百个键）与将来的按应用覆盖属于这一类，另立设计（见 §5）；
码表（约 20 个字段）继续用 R8.1。

## 3. 前置能力（core 侧）

| 能力 | 用途 | 形态 |
|---|---|---|
| 解析后的主题值 | R8.1「跟随主题（值）」 | 新 RPC `theme.resolved`：返回当前主题对外观可覆盖键（字号、字族、字重、翻页栏/页码显示、主字颜色、角标颜色）解析后的值；切换主题后设置端重新拉取 |
| 跨方案覆盖汇总 | R8.6「已被 N 个方案覆盖」 | 新 RPC `schema.overrideSummary`：返回 `{config_key: [schema_id…]}`，只含可见方案；数据源为各方案折叠后的 `Option` 字段 + `[candidate]` / `[punct]` 行为段 |
| 跟随值 | R8.2「跟随全局（值）」 | 不需要新能力：设置端已有整份全局 config |

两个 RPC 都放在主仓 wind-rpc，设置端 mock（`rpc.rs`）同步补上。

|---|---|---|---|---|

## 5. 不在本文范围

- **C2-26 / C2-41 通用 config 方案覆盖（列表式）**：另立 `docs/design/schema-config-override.md`。
  已知约束：
  - 合并不能放在 `Config::load` 里，否则设置端 `config.get` 会把方案值当用户值写回；
    应在 `ConfigBundle::build` 时派生生效配置（`[mobile]` 已踩过这个坑）；
  - 要先修订 R2「键级合并不得扩大」；
  - 要收编现有三套逐字段方案机制（`resolved()`、`[candidate]` / `[punct]` 代际覆盖、方案固定参数）；
  - 引擎侧配置镜像与 `engine_reload_needed` 会把 `schema.*` 的变化判为重建引擎。
- **C0-7 按应用切方案**：第二期。需要一条不写盘的方案切换路径（现在 `finish_user_schema_switch`
  会把 `schema.active` 写进用户 config），还要处理懒加载引擎的秒级延迟、compat.toml 的重载与编辑入口。
- **C2-20 设置项隐藏 / R5 受众分级**：与本文正交。

## 6. 验收

- R8 写入 `config-design-rules.md`，并在附录 checklist 第 6 步加一句「可覆盖项按 R8 呈现」；
- F1–F9 每项都有设置端的渲染测试或快照断言：不勾时显示「跟随X（值）」、勾上后写入、取消勾选后写回未设置；
- F7 迁移有 Value 层单测：旧 `auto` / 6 位 / 8 位三种输入各一例；
- 全仓 grep 设置端文案，「默认」不再用于表示跟随（出厂值语义除外）。
