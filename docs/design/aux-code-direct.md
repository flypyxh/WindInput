# 直接辅助码（双拼）

状态：设计已确认（2026-09-29），待实施。
来源：[GH#129](https://github.com/huanfeng/WindInput/issues/129)、论坛 [t181](https://forum.windinput.com/topic/181)。
前置：`aux-code-schema-source.md`（取码接口 `AuxCodeLookup`、方案来源、后台预热），其附录 A 是本文的调研输入。

## 1. 问题

辅助码今天只能「按引导键进入筛选态」（双拼出厂反引号）。双拼用户的通行习惯是**不按引导键**：
在音节后直接敲 1～2 位形码，输入法自动判定末尾是辅码，把字形对得上的字词提到前面。
GH#129：`uidu` 第一页是「湿度 / 适度 / 十度 / 试读」，想要「释读」得再按反引号，「比较不自然」。

## 2. 决定（已与维护者逐条确认）

| 项 | 决定 |
|---|---|
| 范围 | **只做双拼**（主方案）。全拼 `lim` 既可能是 li+m 也可能是「厘米」简拼，歧义大；自然码 / 手心 / 万象也都是双拼形态 |
| 机制 | **候选后处理、无状态**：每键按奇偶拆「前缀 + 末 1～2 位」，前缀单独解码，筛选后并入主候选。不动拼音引擎切分 |
| 词组规则 | **任意字**（自然码做法），代码按枚举预留 `First` / `Last` 等规则，首版不暴露配置 |
| 位数与歧义 | 按通行习惯（§3 调研）：1～2 位；偶数长度全音节解析优先；奇数长度命中排前（长句保首选） |
| 引导键模式 | 并存，互不替代 |
| 出厂 | 关 |

未采用：辅码并进音节切分（万象 Pro / 墨奇的拼写运算做法，能在整句中间带辅码，但要改切分与词图核心，
组合暴涨）；万象 Lua 式状态机（只覆盖两字词、靠缓存与「首选变三字」闸门，退格编辑易错）。
将来要升级到切分方案，本文的匹配与排序规则可复用。

## 3. 通行做法调研（摘要）

读过源码的三家：万象（`lua/wanxiang/super_lookup.lua` 的 `enable_direct`、`wanxiang_algebra.yaml` 直接辅助段）、
魔然辅筛（rimeinn/rime-moran `moran_aux_translator.lua`）、墨奇（gaboolic/rime-shuangpin-fuzhuma）。

- 位数 1～2；单字常用 2 位，词组常用 1 位。
- **偶数长度全音节解析优先**：四家一致——整句 / 满长词在前，辅码结果在后或只在前几位按频率混排，不无条件抢首位。
  魔然：先 1 个整句，再「最多 2 个满长词 + 辅码首选」。
- **奇数长度末 1 位当辅码**，命中排前；魔然在输入 > 5 码时先给整句，防首选长度来回跳。
- 无命中不清空候选（带引导键的插件才删）。
- 上屏连辅码一起吃掉，剩余输入照常继续。

手心、自然码官方未找到一手规则。

## 4. 生效条件与切分

全部满足才生效：

- 当前活跃方案是双拼（`[engine.pinyin] scheme = "shuangpin"`），走主输入路径；临时拼音、混输首版不做；
- 辅助码生效（`enabled`）且直接辅助码生效（`direct`，§7）；
- 输入 ≥ 3 键，且不在引导键辅助码态；
- 辅码来源可用：方案来源的系统层未就绪时本键不做直接辅助、候选原样，派后台构建（与引导键模式同一处理）。

切分（每键重算，不留状态）：

| 输入长度 | 前缀 | 辅码 | 例 |
|---|---|---|---|
| 奇数 ≥ 3 | 前 n−1 键 | 末 1 位 | `uiduc` → `uidu` + `c` |
| 偶数 ≥ 4 | 前 n−2 键 | 末 2 位 | `uidupl` → `uidu` + `pl`；`xlrn` → `xl` + `rn` |

前缀含手动分隔符 `'`，或不能完整切成双拼音节时，本键不做直接辅助。

## 5. 候选来源与匹配

**来源**：对前缀单独调一次引擎解码，取**完整覆盖前缀**的词与单字（含用户词），**不含**整句候选；
词组长度受现有 `max_phrase_len` 约束。命中项之间保持前缀解码的原顺序。

**匹配**（「码」= 该字在 `AuxCodeLookup` 里的任一编码，一律按编码**开头**匹配，与引导键模式同口径）：

| 候选 | 1 位 `a` | 2 位 `ab` |
|---|---|---|
| 单字 | 某码以 `a` 开头 | 某码以 `ab` 开头 |
| 词组（`Any`） | 任一字的某码以 `a` 开头 | ① 任一字的某码以 `ab` 开头；或 ② 存在 i < j，第 i 字某码以 `a` 开头、第 j 字某码以 `b` 开头 |

规则类型：

```rust
pub enum DirectPhraseRule {
    Any, // 首版唯一实现
    // 预留：First、Last —— 加分支 + 配置值即可，筛选入口不变
}
```

## 6. 排序与上屏

**插入点**：协调器 `build_candidates` 里、按消费长度重排与去重之后、`apply_shadow` 之前。
放在 `build_candidates` 而不是 `update_candidates`：翻页（`expand_candidates`）只重跑前者，放后者会在翻页时丢失。

| 情况 | 结果 |
|---|---|
| 无命中 | 候选原样 |
| 奇数长度，前缀 < 3 音节 | 命中项排最前，其余去重接后 |
| 奇数长度，前缀 ≥ 3 音节 | 引擎首选（通常是整句）保留第 1 位，命中项从第 2 位起 |
| 偶数长度 | 覆盖全部输入的完整候选（词或整句）最多保留前 2 个，命中项接其后，其余再往后 |

两个数（奇数门槛 3 音节、偶数保留 2 个）首版为常量，理由见 §3（魔然默认值）。

已知取舍：整句党每打奇数键，末位其实是下一音节的声母；门槛以下时它仍会被当辅码提升两字词。
这是直接辅码的通病（万象干脆只做两字词），门槛用来保住长句的首选。

**上屏**：

- 命中项标记为消费整个输入（`consumed_length` 取整串），上屏后组码清空；已上屏的前段照常拼接；
- 调频与学习记在前缀的拼音编码下（「释读」记 `shidu`），辅码字母不进词频；
- 退格回滚按原始按键串，与普通候选一致；
- 选未命中的普通候选：按其自身消费长度走，行为不变。

**组码区**：高亮命中项时显示「前缀音节 + 空格 + 辅码」（如 `shi du p`），让人看出末尾被当成了辅码，
与引导键模式同口径。

**与引导键模式**：直接辅助的结果上仍可按反引号进入引导键筛选，筛当前整张候选表；
进入引导键态后直接辅助停用。

## 7. 配置

沿用 `enabled` 的全局 + 方案级三态分层（`schema-config-layering.md` §4）：

```toml
[schema.pinyin.aux_code]
direct = false        # 新增，全局基线，出厂关

# 方案级 [engine.aux_code]
direct = true         # 可选；不写 = 跟随全局
```

- `direct` 只在 `enabled` 也生效时起作用：`enabled` 是总闸（码表加载），`direct` 只决定是否自动判定辅码；
- 全拼写了 `direct = true` 不生效，日志告警一次；
- 出厂两级均关：它改变末尾字母的语义，要用户表态；
- `shuangpin.schema.toml` 不写 `direct`，注释给出开启写法。

## 8. 码表格式：一行多码

为能直接导入 GH#129 附的手心表（`七=a p`）：

- 加载器把 `=` 右侧**按空白拆成多个码**。今天整段 `a p` 被当成一个码，`p` 永远匹配不上；
- 非 UTF-8 文件：日志明确告警「请转存为 UTF-8」并产出空表。全仓无 GBK 解码依赖，不为这一个文件引入 `encoding_rs`；
- 文档写明两条。

## 11. 验收

**纯函数单测**（wind-aux-code）：切分（奇 / 偶 / < 3 键 / 含 `'` / 前缀不成音节）；§5 匹配表逐格一例；
`max_phrase_len`；§6 排序三种情况与无命中；一行多码与非 UTF-8 告警。

**协调器**（小码表夹具）：`direct` 关 / `enabled` 关 / 全拼 / 引导键态中四种不生效；选中命中项组码清空、
词频记前缀编码、退格回滚；翻页后命中项仍在；组码区显示。

**真实数据**（`build_dev/data`，缺数据跳过；小鹤双拼 + `flypy_full.txt`）：

- `uidup` → 首选「释读」（释 = `pl`；同音的湿 `dy`、适 `zk`、十 `al`、试 `yg` 都不以 `p` 开头）；
- `uidupl` → 首选「释读」（`pl` 不是合法小鹤音节，无全音节候选可保留）；
- `goqkk` → 国庆、国情命中（国 = `ky`）；`goqkg` → 只剩国庆（庆 = `gd`，情 = `xo`）；
- `xlr` → 像（`rn`）；`jxl` → 架（`lm`）；
- 连打整句不受扰：3 条 6 音节句子逐键输入，**偶数键**首选与关闭直接辅助码时逐键一致；
- 变异：偶数保留数改 0、奇数门槛改 99，整句用例须变红。

**性能**：开关前后单键耗时，基准各 ≥ 3 次，退化 > 10% 回头看。
